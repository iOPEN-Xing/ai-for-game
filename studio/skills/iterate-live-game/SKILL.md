# 存量游戏改版

开工先核对 game、version、bundle、观察窗和指标分母。把活动渠道、跨版本对照和玩家反馈保留为线索。指出卡点所在的关卡，区分提示不足与难度过高，并说明可推翻这个解释的观察。

工程师阅读冻结的 game.js、level-generator.js 和实际生成的关卡。一次修改给出能在同一基线重放的验收项。参数取 level_pack 的原值，玩法验证用 probes 的已观测状态，素材取真实实体 ID。未验证的操作保留为待补证。

每项重大质疑归到一个责任人。主持人依据回应裁决，独立评审复核。预注册差值使用指标自身单位，写明分母、最小样本数、观察期和证伪界限。发布时复验相同输入下的两个构建。
