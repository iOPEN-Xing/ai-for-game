# 实现一局可验证的游戏

读取本次下发的 ABI、已确认的 GDD、美术参数和上一版本真实源码。游戏模块可以复用基座的状态更新、绘图和自动试玩函数。改动输入或目标时，同步更新可达成目标的试玩输入序列。

把状态保留在可序列化对象中。使用关卡传入的点位、网格和 Seed。动画时间从 tick.dt 累加。渲染读取状态，避免绘制过程改变下一帧的判定。先检查输入有效性，再计分或推进进度。终局后重复输入不应二次结算。

路径关卡验证出生点和终点连通。操作型关卡同时检查可操作时间、命中半径和目标配额。在首关、中间关、末关复盘同一组 Seed，区分参数变化与随机样本变化。发现坏种子，把失败输入与构建诊断一起交给下一次修复。

路径解谜的出生点、终点、可行走格和尺寸都从关卡蓝图读取。手工布局由关卡程序员在 parameters 中提供 grid、from 和 to。构建器会独立寻路，用真实点击在发布模块逐格走到终点。

witness 只能发出玩家能做的 tap、key 或正常时钟 tick。它应读当前关卡和状态来决定下一步。不要由它直接写入分数或通关状态。绘图命令只使用 ABI 的原语。验证玩家有机会失误或超时，并能从全新状态重试。

参考 [MDN 游戏循环](https://developer.mozilla.org/en-US/docs/Games/Anatomy)。

## 失败回放的修复

读取 sample_level 中实际存在的状态和坐标。见到 witness cannot win 时，核对关卡种子、命中数、经过时间、最后输入与胜负状态。witness 得到状态副本，每次只能返回一个真实玩家输入或合法的 tick。时间推进来自 tick，命中位置须与绘制及判定坐标一致。修复时从 previous_submission 或 starter 中最近一次的源码出发，保留已验证的玩法和视觉。比较修复前后的相同输入，再验证其他种子。
