# 约束一次迭代能声称什么

先核对观察窗、线上版本、分流单位、分子和分母。零样本写成缺失。验收试玩属于生产记录。分析玩家表现时保留未完局开局，检查幸存者偏差。关卡样本会随着通关条件筛选，跨关差异本身无法解释原因。

专家先独立提出一种可观察解释。开发角色将建议定位到当前 game.js 或 level-generator.js 的具体状态和参数。评审给出一个能让团队改变主意的反例，主持人据此收敛到一次可实施的变更。

读取冻结的活动入口分组，逐个入口核对访问、开局、自然完局和点击行动按钮的去重人数。同一浏览器可访问多个入口。点击率以带按钮入口的访问玩家为分母，用百分点表达实验差值。渠道来源由玩家自行选择，渠道间的差异只能作为下一轮实验的线索。订单、安装或收入需要业务系统确认。

当报表的 inference_mode 为 descriptive，只报告已观测的人数、比例和分母。没有对照时写“暂时无法估计改版差值”。未接入的订单系统表示缺少订单数据。预测区间来自提案，观测差值的统计区间由结算程序计算并提供。

预先写明北极星指标、差值单位、相对哪个对照、预期区间、每组所需独立玩家数、实验周期和证伪条件。引用已生效知识的 ID。观察型数据只支持现象描述；估计区间的命中与统计显著性是不同的问题。

结算时先核对基线和实际交付的版本，再核对样本和指标差值。交付错位记录执行问题，样本或度量不足保留为未验证，反复被证据推翻的假设进入知识修订。稀疏数据不能升级成通用游戏规律。
