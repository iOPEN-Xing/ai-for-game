# 回路制作室 v1

这个版本面向有活动流量、需要持续迭代小游戏的内部运营团队。团队在制作台定义目标、批准方案和验收版本，玩家通过公网链接试玩。上线后可以沿同一条记录查到哪个构建被玩过、团队改了什么、观察到的结果是否落在事先写下的区间内。

| 原案例环节 | v1 的实现 | 可以核对的交付物 |
| --- | --- | --- |
| 制作人和专业分工 | AgentScope 驱动 8 个生产角色。有改动时制作人判定影响范围，按节点复用成果。调研员读取选图像素，每个方向保留 2–3 张美术参考，用户只选一张时保留该张 | 方向、逐图观察、发送给美术师的原图摘要、实体参考关系和构建清单 |
| 关卡工厂与共用宿主 | 新构建包含 `level.json`。运行时模式保存参数和 Seed，由工厂现场生成。预制模式保存验算后的完整布局。宿主向游戏传入本关配置，服务端按同一份构建回放 | 蓝图、发布包和玩家成绩可以逐关核对。旧构建继续使用自己的内置关卡 |
| 主持人和专家团 | 运营侧有主持人、数据分析师、开发工程师、游戏设计师和评审五个角色。先独立取证，再质询、答辩、裁决和终审。存量改版及新游戏立项有各自的提示、证据和审批条件 | 可被受理的提案、逐项裁决或明确的补证清单 |
| 每日运营和经验回收 | 北京时间 08:00 处理前一自然日。到期实验先结算。配额耗尽时将未处理候选及基线保存在日报内，下一自然日恢复。切换版本后记录跳过原因 | 观察窗、提案 ID、采纳的参数、预注册范围、结算及知识审批记录 |
| 上下文、记忆和技能 | 生产与运营共 13 个角色，使用五份按角色和任务分配的项目手册。执行时固定手册正文、系统提示、项目偏好和证据。编辑者偏好可以被项目覆盖 | 从私有制作台检查节点输入、参考图、执行记录及 SHA-256 |
| 公网试玩 | 阿里云轻量机使用应用和 Caddy 两个容器。公开域名仅开放玩家流程，团队经 SSH 管理。开局在文件读取后重新核对分流，回放先验算再记分 | 版本切换期间的一致开局、可撤销登录、按日存储额度、可加密上传的快照及恢复演练 |

图中企业数仓对应本版的 SQLite 日报。远程编码容器对应受限的 JavaScript 生成、构建和执行环境。模块使用 `./game` 导出协议。音频按美术规格合成，当前交付覆盖交互、状态、UI 和背景音轨。真实玩家留存变化、活动转化和团队制作成本需通过业务试点计量。

## v1.1 工程更新

本版在隔离环境通过 64 项回归和 17 个离线评测案例。另以 GLM 5.4 实际完成 4 个合成任务，覆盖单实体重绘、单音轨编辑、带干扰的首评和已知死路复核。团队制作和玩家试玩在真实 Chrome 验收。业务效果仍由各游戏预注册的正式样本衡量。

- 制作台按版本订阅调研草稿。单音轨修改保留其他音轨和贴图，局部重绘保留已有的策划与游戏代码。
- 运营评审逐项核对已知死路 ID。实验结算记录原假设、实际交付和实测差值。团队可追溯审核意见，也可按历史截止时间还原当时可见的知识。
- 团队入口提供执行器心跳和模型尝试指标。离线验收统一运行源代码检查、路由、脚本、固定样例与回归。在线 GLM 验收使用合成请求和临时数据库。
