## AgentScope 如何参与（explicit message passing）

项目采用官方 skill 中的 **explicit message passing**。Python 状态机掌握调度权（Producer/主持人唯一调度者，路由经 Structured Output 统一做出），每次角色调用构造专属 Agent 和系统提示。首轮允许并发，角色看不到同轮其他专家的推断。后续阶段只接收程序明确交接的材料。首轮事实共享同一版冻结快照，独立性来自可见信息和会话隔离，各角色仍然使用同一模型。生产用 reply 输出结构化交付物，调研报告用 reply_stream 提供阶段性文本。

单次分析最多同时调用三个角色（SRS NFR-8 成本护栏）。首评中的重大异议与评审发起的质询都进入问题清单。每条回复、裁决与复核分别保存。程序关联编号，主持人不能通过漏写编号移除问题。业务证据不足进入待补证，技术调用中断则按任务检查点恢复。人工补证重开会保留旧快照和旧论证，并建立新快照。实现与依据见[角色适配层](../studio/agents.py)、[状态机和最终判定](../studio/domain/deliberation.py)及[AgentScope 官方编排说明](https://github.com/agentscope-ai/skills/blob/b5336640300f4c96818065c5d645df813/skills/agentscope-skill/references/multi_agent_orchestration.md)。

## 上下文、记忆与偏好（对照 img-58 四层记忆）

| 材料 | 谁能看到、什么时候读取 | 如何复核 |
| --- | --- | --- |
| 项目规则与任务手册（核心规则层：常驻注入） | 程序把批准的角色、任务和阶段手册放入系统提示。外部检索和历史记录作为输入材料，匿名反馈只提供分关卡评分汇总 | 查询该节点的完整归档系统提示，核对摘要、角色和技能版本 |
| 当前任务与实际证据（历史记忆层：原始事件唯一可引用） | 冻结游戏、版本、构建、周期、分母、关卡、源码、输入探针和知识 ID。工程师与评审可读源码，其他角色读可见的结构化事实 | 模型的证据 ID 必须出自该角色的目录。引用是否支持具体推断由独立评审和人审判断。正式样本与当前构建不匹配时阻止归因（R-EVIDENCE） |
| 项目经历与经验（知识层：按游戏+玩法召回，引用带匹配分） | 制作阶段保存已确认方案、试玩和返工意见。项目记忆按相关范围读取，运营另检索同玩法已生效知识及本游戏已知死路 | 单独保留事件、实验、知识状态和来源。审核人可以逐条指定哪项已有知识被新证据推翻（三层归因，不批量连坐） |
| 个人与项目偏好（会话+项目覆盖） | 制作台「知识与记忆 → 制作偏好」可设置受众、风格、操作、声音及应避免的设计。新项目复制创建者的默认值，可单独覆盖。每个新版本、带理由的主动返工或新提案都会保存项目快照 | 浏览器使用独立随机凭证，服务端保存其摘要，写入校验版本号。分析师只取受众及应避免事项，美术角色可取画风和音频偏好。游戏玩家行为只用于运营观测 |

同一次任务重试会读取已固定的模型和技能正文。每个模型节点保存角色、模型路由、阶段、系统提示摘要、实际初始输入摘要、文本字节数、图像摘要和本次适配器调用次数。制作台可打开该节点的文本入参和系统提示。选中的图像按实际送入模型的 JPEG 字节归档，规则检索结果有单独检查点。外部网站变化后，重试仍然使用冻结的资料。审阅人可以查看当时的图片。文本输入有 160,000 字节上限，优先裁剪旧的比较资料并记录数量。必要源码和证据仍超限时任务会明确报错。实现见[上下文与记忆](../studio/context.py)、[版本和提示固定](../studio/skillbook.py)及[私有接口](../studio/api/library.py)。

个人默认值依靠当前浏览器的凭证识别。清除该凭证后会获得新的个人档案。一个制作室的项目与项目偏好对获准进入该制作室的编辑者共享。跨设备身份、组织权限和多租户隔离属于后续产品范围（SRS FR-9，P6 落地）。

## 业务价值与上线条件

首个适用客户是能连续开展活动、掌握入口流量并能复核结果的运营团队。该团队可以量出做出可玩版本所需的人时、每个获批改动的兑现率、错误实验拦截数、活动入口点击及首玩次日回访。最直接的一次验收是拿一条"降低首关流失"的建议，查到它依据的玩家、改过的参数、上线的包和最后的效果。付费意愿、获客成本、真实留存提升和收入仍需客户试点验证。[试点与经营指标](PILOT.md)

当前部署目标是带持久卷的单实例（`workers=1`，ADR-002）。Web 与任务执行器共用 SQLite WAL，文件锁选出一个执行器，任务有心跳、有限重试和产物检查点。公网形态追加 Caddy 反代（TLS + `/cartridges/v1/*` immutable 缓存）与数据库、构建和素材的快照备份（`deploy/backup.sh`），完整拓扑与一页恢复见 `RUNBOOK.md`。接入正式客户前仍要按目标流量验证并发（k6 三场景）、模型费用与延迟、整库和素材备份恢复。订单或报名转化需要相应业务系统对账。运营判断与玩法乐趣都保留人审。
